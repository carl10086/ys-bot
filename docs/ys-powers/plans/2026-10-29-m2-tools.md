## 依赖图

```
T1 agentd（VM 内进程）
  └─→ T2 宿主准备（rootfs 烤 agentd + tap 网络）        【检查点 1：宿主基建可用】
        └─→ T3 vmhostd（VM 生命周期 + 代理 + catalog）  【检查点 2：Mac → VM 调用链通】
              └─→ T4 worker 工具 loop（RemoteDriver + workflow 工具分支）
                    └─→ T5 端到端冒烟                    【检查点 3：验收标准 1/2/3】
```

每个 T 是竖切：交付一条完整可验证的路径，不是"先写完全部 proto 再写全部实现"。

## 横切决策（开工前先定，各任务引用）

| 决策 | 定案 | 理由 |
|---|---|---|
| proto 工具链 | **buf**（`buf generate`，protoc-gen-go + protoc-gen-connect-go，均 `go tool` 管理） | 与 sqlc 同模式：生成物入 gen/ 不手改；e2b envd 也用 buf |
| 工具 loop 位置 | **Temporal workflow 内**，不用 fantasy 内置 agent loop | 每步（tool_call/tool_result）独立 activity 落库 = 讲座"每步落库" + 崩溃可恢复；fantasy 只用到 model 级 `Call{Tools}` 原语 |
| 工具 loop 上限 | 单 turn ≤ 20 次工具调用，Exec 默认 timeout 60s | 防失控 |
| sandboxes 写入方 | ys-server/worker 建行（creating）；vmhostd 填 slot/vm_ip/status | data-model.md 2026-10-29 修订 |

## T1 agentd 最小实现

**产出**：`cmd/agentd` + `internal/agentd`（Connect-RPC server）+ `proto/agentd/v1/agentd.proto` + buf 工具链

**协议**（spec §2，M2 全量）：

```proto
service Agentd {
  rpc Health(HealthRequest) returns (HealthResponse);
  rpc Exec(ExecRequest) returns (ExecResponse);       // 同步跑完返回
}
message ExecRequest  { string cmd = 1; string workdir = 2; uint32 timeout_sec = 3; }
message ExecResponse { int32 exit_code = 1; string stdout = 2; string stderr = 3; }
```

ReadFile/WriteFile proto 里先不写（工具只有 shell；spec 已拍）。

**验收**：
- `buf generate` 产出 gen 代码，`go build ./cmd/agentd` 通过（`CGO_ENABLED=0` 静态）
- Mac 本地起 agentd :4998，connect client（或 curl JSON）调 `Exec{cmd:"echo hi"}` → `stdout:"hi\n"`、exit_code=0
- `Exec{cmd:"exit 3"}` → exit_code=3；`timeout_sec=1` 跑 `sleep 5` → 超时错误
- `go test ./internal/agentd/...` 过

## T2 宿主准备（152 上手工，产出两个脚本入 `scripts/`）

**产出**：`scripts/build-rootfs.sh`（把 agentd 烤进 rootfs 模板）+ `scripts/setup-host-net.sh`（NAT）

- build-rootfs：`cp` bionic rootfs → loop mount → 放 agentd 静态二进制 + systemd unit（:4998 拉起）→ umount，产出 `rootfs-agentd.ext4` 模板
- setup-host-net：`sysctl -w net.ipv4.ip_forward=1` + iptables MASQUERADE（10.200.0.0/16 出公网）+ 持久化说明
- VM 内网络：boot 参数/init 配 `10.200.{slot}.2/30` + 默认路由 + DNS（8.8.8.8）

**验收（检查点 1）**：
- 手工起一台 VM（复用冒烟的 boot-vm.sh 改造）：宿主 `curl 10.200.0.2:4998/health` 通、`Exec` 通
- VM 内 `curl -sI https://mirrors.opencloudos.tech` 通（NAT 出公网验证）

## T3 vmhostd

**产出**：`cmd/vmhostd` + `internal/vmhostd`（Connect-RPC server：生命周期 + 代理）+ `proto/vmhostd/v1/vmhostd.proto` + sandboxes schema 落地（schema.sql + sqlc 重新生成）

**协议**：

```proto
service Vmhostd {
  rpc EnsureVM(EnsureVMRequest) returns (EnsureVMResponse);   // {sandbox_id} → {agentd_endpoint}
  rpc DestroyVM(DestroyVMRequest) returns (DestroyVMResponse);
  rpc StatusVM(StatusVMRequest) returns (StatusVMResponse);
  rpc Exec(ExecRequest) returns (ExecResponse);               // 代理：{sandbox_id, cmd...} → agentd
}
```

**职责**（spec §1 vmhostd 侧）：slot 空闲最小值分配（`UNIQUE(host_id,slot)` 兜底）、`cp --reflink` 建 rootfs、tap 建/拆、firecracker API 编排、agentd health 轮询、Redis catalog（`sandbox:host:{id}`）+ 心跳（`vmhostd:alive:{host_id}` TTL 30s）、启动 reconcile（标 stopped 释放 slot）

**验收（检查点 2）**：
- 152 上跑 vmhostd（nohup 即可，systemd M3 再说）；Mac 上 `redis-cli keys 'vmhost:alive:*'` 可见心跳
- **从 Mac** 调 `EnsureVM{sandbox_id}` → 返回 endpoint → 接着调 `Exec{sandbox_id, cmd:"hostname"}` 返回 VM 主机名
- PG 里 sandboxes 行：slot/vm_ip/status=awake 已填；`DestroyVM` 后进程/tap/目录/catalog 全清，行标 stopped
- reconcile 验证：手工 `kill -9` 一个 firecracker 进程 → 重启 vmhostd → 对应行变 stopped

## T4 worker 工具 loop

**产出**：`internal/vmdriver`（Driver 接口 + RemoteDriver 实现）+ `internal/agent` 工具调用扩展 + `internal/workflow` 工具分支

- `agent.Agent` 接口演进：`Reply` → `Step(ctx, history, tools) (StepResult, error)`，`StepResult` = 文本 或 []ToolCall；fantasy 类型仍不出包（红线沿用）
- workflow 工具分支（spec §4）：CallLLM 有 tool_calls → 首个前 EnsureAwake → ExecTool activity（经 RemoteDriver → vmhostd → agentd）→ tool_call/tool_result 各写一条 messages + PublishChanged → 继续，≤20 次
- `sandboxes` 读取侧 queries（GetSandboxByUser 等）随 sqlc 生成

**验收**：
- `go test ./...` 全过（mock Driver + mock agentd client：断言 loop 形状、上限、每步落库）
- 集成（真 152）：SPA API 触发 turn，prompt"列出 /etc 前 5 个文件" → messages 表出现 tool_call + tool_result（含真实 /etc 内容）+ assistant

## T5 端到端冒烟（检查点 3 = spec 验收标准）

1. SPA 发"看看你 /etc 下有什么" → tool_call / tool_result / assistant 三条消息按 seq 按序回显
2. 同用户再发一条用工具的消息 → VM 复用（sandboxes 行不变，无新 slot）
3. turn 进行中 `kill` ys-worker → 重启 → turn 恢复完成，无重复 tool_result
4. 设计文档归档：spec 标"已实现"，plan 标完成日期

## 风险与备注

- **T2 是手工活最重的**：rootfs 里 systemd 配网（bionic = netplan）可能踩坑，预案：不行就把 IP 配置写进 agentd 启动前置脚本（ip addr add）
- **fantasy model 级 tool 调用**在 v0.45.5 的 API 形状（`Call.Tools` / response 里的 ToolCallContent）以实际代码为准，T4 第一步先写 5 行 probe 确认
- **exec 输出大小**：ExecResponse stdout 不截断会撑爆 messages.content——T4 写库前截断到 10KB（尾部保留）
- 全程不动 M1 已验收行为：纯对话 turn 不得触发 EnsureAwake（懒唤醒红线，T4 测试里显式断言）
