# M5 实施计划：记忆与技能（memory/skills）

> 依据：`docs/ys-powers/specs/2026-11-02-m5-memory-design.md`（2026-11-02 定稿）。
> 方式：TDD，每任务红→绿→提交。工作区：直接基于 main。
> M4 经验直接适用：sqlc 子查询限定表名防 ambiguous；test env 默认 activity 重试，失败 mock 不用 `.Once()`；
> 起 workflow 一律走 activity 里 `client.ExecuteWorkflow`（不用 fire-and-forget child）；测试库按包分配不共用。

## 任务总览与依赖

```
T1 PG 存储层 ──┬─→ T2 提取管线 ──┐
               ├─→ T3 注入 ──────┼─→ T4 turn 接线 ──→ T6 e2e 验收
               └─→ T5 memory 工具 ────────────────→
```

- **CP1（T1 后）**：存储就绪——三表可查，ops 事务+审计可单测
- **CP2（T4 后）**：主链路闭环——说偏好 → pass 提取 → 新会话注入，可手动验证验收 1
- **CP3（T6 后）**：验收 1–7 全过，spec 回填证据

## Task 1: PG 存储层——三表 + 查询 + ops 事务

**Files**: `internal/store/pg/schema.sql`、`queries.sql`、`pg.go`、`memory_test.go`（新）

- schema.sql 加 `memories` / `skills` / `memory_ops` 三表（DDL 照 spec）；索引：
  `memories(user_id, type)`、`UNIQUE(user_id, hash)`、`skills UNIQUE(user_id, name)`
- `ResetSchema` 补 drop 三表（测试库重建用）
- queries.sql（sqlc 生成后门面包装）：
  - 注入四查询：`ListProfileMemories`（type=profile，importance DESC, updated_at DESC，LIMIT 100）、
    `ListRecentLogMemories`（type=log，created_at DESC，LIMIT 30）、
    `ListActiveNotes`（type=note 且 expires_at 未过）、`ListSkillCatalog`（只出 name+description）
  - ops 原语：`AddMemory`（`ON CONFLICT (user_id,hash) DO NOTHING`，`:execrows` 探测去重）、
    `UpdateMemory`、`DeleteMemory`、`UpsertSkill`、`DeleteSkill`、`InsertMemoryOp`
  - 工具支撑：`SearchMemories`（ILIKE 关键词，memory+skill 内容）、`GetMemoryByID`、`GetSkillByName`
  - pass 支撑：`ListAllMemoriesForUser`（提取上下文）、`ListTurnMessages(sessionID, turnID, batchSeqs)`
    ——注意 `messages.turn_id` **仅 assistant 行有**，用户消息靠 batch seq 列表兜（`turn_id=$2 OR seq=ANY($3)`）
- `pg.go`：`ApplyMemoryOps(ctx, userID, ops, source)`——pgx 事务内逐条应用（序号→UUID 由调用方解析好），
  每条配一行 `InsertMemoryOp` 审计；用 `q.WithTx(tx)`（gen 已支持）

**Acceptance**: 三表建好；ops 三种操作 + 审计 + hash 去重 + note 过期过滤均有单测
**Verify**: `go test ./internal/store/pg/`（YS_TEST_PG 库）全绿
**Dependencies**: 无

## Task 2: 提取管线——MemoryPassWorkflow

**Files**: `internal/workflow/memory.go`（新）、`activities.go`、`cmd/ys-worker/main.go`、`memory_test.go`（新）

- `memory.go`：`MemoryPassWorkflow(userID, sessionID, turnID, batchSeqs)` →
  `LoadTurnMessages` → `LoadMemoryState`（全量记忆+skills）→ `ExtractMemories` → `ApplyMemoryOps`
- **序号映射**（mem0 防幻觉技巧）：提取前把记忆/技能 UUID 映射为 1,2,3… 喂给 LLM；
  ops 回来后映射回 UUID——纯函数 `numberMap`，单测覆盖
- `EXTRACT_PROMPT` 常量（规则骨架照 spec：语义重复→none / 信息更全→update / 矛盾→delete+add /
  流程性沉淀→skill / 相对时间落成绝对日期 / 输出 JSON ops）
- `ExtractMemories` 用**独立 LLM 实例**：`main.go` 建第二个 `agent.NewFantasy`
  （Model = `envOr("MEMORY_MODEL", LLM_MODEL)`，System = EXTRACT_PROMPT——正好用上"构造期固定 system"的既有形状）；
  `Activities` 加 `MemoryAgent` 字段。JSON 解析失败 = activity 报错，交给 Temporal 重试，最终失败只影响本 pass
- main.go 注册 `MemoryPassWorkflow`

**Acceptance**: fake MemoryAgent 返回固定 ops → 断言库内终态 + 审计行；update/delete 裁决路径各有用例；
序号映射纯函数单测；LLM 失败 → workflow 报错但**无 .Once() mock**（test env 默认重试）
**Verify**: `go test ./internal/workflow/`（YS_TEST_PG_WF 库）全绿
**Dependencies**: T1

## Task 3: 注入——BuildSystemPrompt + system 消息通道

**Files**: `internal/agent/agent.go`、`activities.go`、`turn.go`、`cmd/ys-worker/main.go`、测试

- `agent.go`：`Step` 的 role switch 加 `case "system"` → 插为 fantasy system 消息
  （注入的系统提示作为 history[0] 传入，不落库、不经 PG 投影）
- `activities.go`：`BuildSystemPrompt(ctx, userID)` —— `BasePrompt`（新字段，main.go 从 `LLM_SYSTEM` 喂入）
  + profile 全量（Go 侧 4000 字符截断）+ log 30 条 + 活跃 note + skills 清单（name+description，不带全文）
- `turn.go`：`LoadHistory` 后 `ExecuteActivity("BuildSystemPrompt")`，prepend `agent.Message{Role:"system"}` 到 history
- `main.go`：`agent.Config.System` 不再赋值（避免与 history 里的 system 双份），改喂 `Activities.BasePrompt`

**Acceptance**: 注入组装/截断/过期过滤单测；`Step` 的 system case 单测；turn 测试断言 CallLLM 收到的 history[0] 是 system 且含记忆块
**Verify**: `go test ./internal/agent/ ./internal/workflow/` 全绿
**Dependencies**: T1

**Acceptance**：turn 测试：fake TC 断言 pass 被触发且参数含 batch seqs；StartMemoryPass 失败时 turn 仍正常完成（验收 6 的单测形态）
**Verify**: `go test ./internal/workflow/` 全绿

## Task 5: memory 三工具——服务端执行路径

**Files**: `activities.go`、`turn.go`、`turn_test.go`

- 工具定义：`memory_search(query, limit?)` / `memory_read(ref)` / `memory_save(type, text, ttl_minutes?)`
- `CallLLM` 工具列表：**无论 Driver 有无都给这三个**（纯对话也要有记忆，spec 验收场景）；有 Driver 再追加 shell
- `turn.go` 工具 loop 分支：`memory_*` 走新 activity `ExecMemoryTool`，**不触发 EnsureAwake**
  （懒唤醒红线：纯记忆对话不碰 VM）；`shell` 照旧
- `ExecMemoryTool(ctx, sessionID, name, input)`：session→userID；search→`SearchMemories`；
  read→`GetMemoryByID`/`GetSkillByName`；save→立即落库 + 审计 `source=agent`（走 T1 的 AddMemory/UpsertSkill）
- 输出统一 JSON 字符串（与 shell 工具落库形状一致）

**Acceptance**: turn 测试：纯 memory_save turn 全程未调 EnsureAwake；三工具各有 happy path + 非法输入用例；
save 后审计 source=agent（验收 4）
**Verify**: `go test ./internal/workflow/` 全绿
**Dependencies**: T1
